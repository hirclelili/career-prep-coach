# 质量门槛

## 经历档案

- [ ] 当前对象的公司/项目、角色、时间没有串到其他经历。
- [ ] 多项目范围已确认，所有选中项目均被覆盖。
- [ ] 每个项目都有背景、个人行动、判断和证据/产出。
- [ ] 内容足够具体，不只是标签和概括句。
- [ ] 团队成果与用户个人贡献边界清楚。
- [ ] 未确认信息使用待补充或 `★`，没有悄悄写成事实。
- [ ] 单段经历 bullet 为 2-5 条，具体且不空泛。
- [ ] 完整故事不是 bullet 的机械扩写。
- [ ] 30 秒版和 90 秒版节奏不同。
- [ ] 至少 5 个追问都有应对思路。
- [ ] 没有诱饵金句模块。

## JD 拆解

- [ ] 岗位使命和要求来自 JD 或明确标注的公开信息。
- [ ] 每个关键要求都有 JD 证据。
- [ ] 隐含要求说明了判断依据。
- [ ] 匹配初判指向真实经历。
- [ ] 拆解后停在确认门，没有提前输出手册。
- [ ] 首轮没有输出自我介绍、题库、案例答案或反问清单。
- [ ] 没有把行业常见动作写成用户已完成的事实。
- [ ] 当前状态是 `jd_received`，没有在同一回复里自行跨到 `jd_confirmed`。
- [ ] 一级标题只来自 JD 拆解模板。

## 面试手册

- [ ] 七章完整且顺序正确。
- [ ] 匹配度只使用规定的四档。
- [ ] 真实缺口没有被包装成“部分覆盖”。
- [ ] 优势和短板都有证据或具体应对。
- [ ] 问题数为 15-20，且不是重复改写。
- [ ] 每题包含考察点、难度、经历、结构、信号、踩坑、示例和追问。
- [ ] 回答示例基于真实经历；缺失时使用占位。
- [ ] 不包含知识体系正文。
- [ ] 不包含 HTML 完成标记。

## 知识体系

- [ ] 开头有 Mermaid 思维导图。
- [ ] 有 2-4 个模块，每个模块有 2-4 个概念。
- [ ] 每个概念解释“是什么”和“怎么用”。
- [ ] 例子具体且与岗位相关。
- [ ] 末尾有应用场景总览。
- [ ] 不是面试题库或术语堆砌。

## 局部优化

- [ ] 只返回目标块。
- [ ] 标题保持不变。
- [ ] 没有误改其他内容。
- [ ] 写回文件前已获得用户明确要求。
