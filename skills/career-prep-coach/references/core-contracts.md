# 核心数据契约

## 1. 稳定经历身份

每段经历必须有稳定、唯一的 `experience_id`。ID 是跨深挖、选材、简历生成和局部优化的唯一关联依据。

- 宿主提供 ID 时原样使用，不能重新生成。
- 宿主没有 ID 时，按首次出现顺序分配 `exp-01`、`exp-02` 等会话 ID。
- 修改标题、公司展示名、角色或时间时，ID 不变。
- 公司名、岗位名、时间和文本相似度只能帮助识别候选对象，不能用于自动合并或删除。
- 不得把 `Product`、`Marketplace`、`运营`、`产品经理` 等通用词当成唯一身份。
- 若疑似重复，列出两个 ID 和差异，请用户确认；确认前均保留。

## 2. 经历类型

每条经历只属于一个一级类型：

- `work`：正式工作。
- `internship`：实习。
- `project`：独立于任职关系的个人、课程、比赛或合作项目。
- `campus`：学生组织、社团、志愿服务等校园经历。
- `entrepreneurship`：创业或独立经营。

实习或工作内部可以包含多个“项目/模块”，但它们仍然属于原任职经历，不能因为正文出现“项目”就移动到一级栏目“项目经历”。

最终简历的栏目映射：

- `work`、`internship` → `工作经历` 或 `实习经历`
- `project`、`entrepreneurship` → `项目经历`，除非用户明确要求单列创业经历
- `campus` → `校园经历`

同一栏目内按结束时间从近到远排列；“至今”视为最新。方向策略可以改变分量和表达角度，不能改变类型和时间顺序。

## 3. 事实层级

按以下层级处理内容：

1. `confirmed`：用户原文或明确确认，可进入正式成品。
2. `inferred`：合理推断，只能作为问题或候选选项。
3. `suggested`：建议补充的工作方法，必须标记并等待确认。
4. `external`：公开搜索信息，只能描述公司、岗位或行业语境。

外部信息、职位常识和 AI 推断都不能变成用户的个人行动、结果或能力证据。

## 4. 决策优先级

发生冲突时按以下顺序执行：

1. 用户最新明确指令。
2. 用户对某条经历的手动包含、排除、顺序、角度和 bullet 数设置。
3. 用户已确认的结构化策略。
4. 经历资产中的已确认事实。
5. AI 推荐。
6. 外部公开信息。

AI 不得用“更适合目标方向”覆盖用户手动选择。若用户要求会导致简历明显过长或重点分散，先说明影响，但仍以用户最终选择为准。

## 5. 状态与完成

- 对话出现过某段经历，不等于经历已归档。
- 有零散追问记录，不等于完整档案已生成。
- 有方向推荐，不等于选材策略已确认。
- 有选材策略草稿，不等于允许生成整份简历。
- 只有实际生成、通过检查并明确交付的内容才是完成产物。

跨会话继续时，先根据现有文件或结构化状态确认对象和阶段；无法验证时，用一句话向用户确认，不要自行把草稿升级为完成状态。
