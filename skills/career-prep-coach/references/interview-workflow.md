# 面试准备工作流

## 目录

1. 输入与对象
2. 可选公开信息补充
3. JD 拆解
4. 确认门
5. 面试手册生成
6. 继续交互

## 1. 输入与对象

优先收集：

- JD 原文。
- 公司与岗位名。
- 用户简历、经历档案或至少 2-3 条核心经历。
- 面试轮次或时间（若用户已知）。

只有 JD、没有经历时仍可拆解岗位，但在匹配诊断和回答示例中明确标记 `[需要你的真实经历]`。

不要把多个岗位合并准备。用户切换 JD 时建立新岗位对象。

## 2. 可选公开信息补充

仅当宿主已有网页搜索工具时执行，不要求用户配置额外 API。

优先级：

1. 公司官网业务与产品页。
2. 公司官方招聘页。
3. 同类岗位公开 JD。
4. 近期可靠业务信息。

搜索结果只用于：

- 理解岗位所在业务。
- 补充面试可能关注的业务场景。
- 校验岗位关键词。

禁止据此补写用户经历、个人成果、公司内部流程或未公开事实。输出中引用关键外部事实时附链接，并说明可能存在时效误差。

## 3. JD 拆解

第一阶段只输出：

```markdown
# JD 拆解：[公司]｜[岗位]

## 岗位使命
[用 2-3 句话说明岗位为什么存在、要解决什么问题。]

## 要求拆解
| 类型 | 要求 | JD 证据 | 重要度 | 面试可能怎么验证 |
|---|---|---|---|---|
| 硬技能 | ... | ... | 必须 | ... |
| 软技能 | ... | ... | 必须/加分 | ... |
| 业务理解 | ... | ... | ... | ... |

## 隐含要求
- [信号词] → [实际要求与判断依据]

## 简历与经历匹配初判
| JD 要求 | 当前证据 | 初判 | 需要补什么 |
|---|---|---|---|

## 需要你确认
- [解析中最不确定的 1-3 点]
```

拆解后停止，不提前输出七章手册。

“帮我准备面试”“分析一下这个岗位”“看看怎么准备”都不等于授权跳过确认门。只有用户明确要求“跳过拆解/直接生成完整手册”才可越过。

把第一阶段视为 `jd_received` 状态，而不是面试手册的前半段。不要在生成拆解后继续推演用户的下一条回复。

本阶段禁止：

- 写自我介绍。
- 扩写用户项目做法。
- 给出完整问题题库。
- 生成案例题答案。
- 把推荐指标、Prompt 方法、RAG 流程等行业常见内容写成用户亲自做过的事。

发送前扫描草稿。若包含以下任一标题或同义内容，删除这些部分，只保留拆解模板：

- 自我介绍
- 项目深挖回答
- 高频问题 / 问题预测
- 回答示例
- 专项知识准备
- 反问面试官
- 下一步准备动作清单

## 4. 确认门

询问：

> 这份拆解是否准确？你可以直接说“继续”，也可以先修正岗位重点、面试轮次或想主打的经历。

只有用户确认、点击等价指令或明确要求直接生成，才进入下一阶段。

## 5. 面试手册生成

读取 [interview-manual.md](interview-manual.md)，一次性生成完整七章。

生成时：

- 每个匹配判断都指向用户真实经历证据。
- 区分“直接命中、可迁移、部分覆盖、真实缺口”。
- 问题预测必须覆盖岗位能力、经历深挖、业务判断、协作与复盘。
- 回答示例优先使用完整经历档案里的故事；证据不足时给结构和占位符。
- 不把知识体系正文混入手册。
- 不输出网页内部完成标记或 HTML 注释。

## 6. 继续交互

手册生成后支持：

- 局部优化某一章。
- 针对某一道题模拟追问。
- 根据用户新补充经历更新匹配诊断和相关回答。
- 生成岗位知识体系。
- 补充一个知识模块。

如果用户问普通问题，直接回答，不必重新生成整份手册。
